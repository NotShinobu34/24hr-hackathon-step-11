# Feature & Asset Provenance Specification

## Purpose

In cadastral surveying and AI-assisted mapping, legal credibility depends on data provenance. A surveyor must know exactly how every polygon, line, and attribute came into existence.

GeoParcel AI enforces strict, immutable provenance tracking across every asset and vector feature.

---

## 1. Extraction Modes

The system explicitly distinguishes between three extraction modes:

1. **`model_inference`**:
   - Feature candidates generated by a live deep-learning / machine-learning inference model (e.g., pretrained segmentation backbone).
   - Subject to hardware availability and inference latency.
2. **`cv_baseline`**:
   - Feature candidates generated by deterministic computer vision algorithms (e.g., OpenCV Canny edge detection, adaptive thresholding, morphological opening/closing, contour approximation).
   - Fast, reliable, deterministic, runs on standard CPU.
3. **`demo_fixture`**:
   - Curated, pre-computed urban vector datasets designed to demonstrate the complete workflow reliably under hackathon or network-constrained conditions.
   - Guaranteed correctness and topology edge-case representation.

### Transparency Rule
The UI and API must **never** claim that `model_inference` occurred if `cv_baseline` or `demo_fixture` was used. The active mode must be visibly badged on every panel and feature card.

---

## 2. Feature Provenance Contract

Every feature returned by the API or exported from the system must include the following provenance metadata in its properties:

```json
{
  "id": "parcel-104",
  "featureType": "parcel",
  "geometry": {
    "type": "Polygon",
    "coordinates": [[[77.5945, 12.9715], [77.5948, 12.9715], [77.5948, 12.9719], [77.5945, 12.9719], [77.5945, 12.9715]]]
  },
  "properties": {
    "source": "ai",
    "sourceAssetId": "asset-ortho-001",
    "processingMode": "cv_baseline",
    "confidence": 0.88,
    "confidenceType": "heuristic",
    "status": "review",
    "edited": false,
    "verified": false,
    "verifierId": null,
    "verifiedAt": null,
    "editHistory": [],
    "area_m2": 245.8,
    "perimeter_m": 62.4,
    "metricCrs": "EPSG:32643"
  }
}
```

### Required Fields Definition

| Field | Type | Allowed Values | Description |
| :--- | :--- | :--- | :--- |
| **`source`** | `string` | `'ai'`, `'ground_truth'`, `'manual'` | Origin of the initial geometry. |
| **`sourceAssetId`** | `string` | UUID or string ID | Foreign key to the source orthophoto or vector file. |
| **`processingMode`** | `string` | `'model_inference'`, `'cv_baseline'`, `'demo_fixture'`, `'manual_edit'`, `'reference'` | Specific mechanism used to generate the candidate. |
| **`confidence`** | `float \| null` | `0.0` to `1.0` | Model confidence or heuristic certainty score. |
| **`confidenceType`** | `string` | `'model_probability'`, `'heuristic'`, `'ground_truth'`, `'n/a'` | Explanation of how the confidence was calculated. |
| **`status`** | `string` | `'detected'`, `'review'`, `'corrected'`, `'verified'`, `'rejected'` | Current lifecycle stage in the survey review queue. |
| **`edited`** | `boolean` | `true`, `false` | Indicates whether a human operator has modified the geometry. |
| **`verified`** | `boolean` | `true`, `false` | Indicates whether a human reviewer has signed off on the feature. |
| **`verifierId`** | `string \| null` | Identifier | User/surveyor ID who verified the feature. |
| **`verifiedAt`** | `timestamp \| null` | ISO 8601 string | Time of verification. |
| **`editHistory`** | `array` | List of edit events | Audit trail: `[{"timestamp": "...", "editorId": "...", "operation": "vertex_move"}]`. |

---

## 3. Asset Provenance

Every source raster or reference vector registered in the project must carry:

- `id`: Unique asset identifier.
- `name`: Original filename.
- `assetType`: `'ori'` (orthorectified imagery), `'drone'`, `'dsm'`, `'dtm'`, `'ground_truth'`.
- `sourceCrs`: Declared or detected CRS of the file (e.g. `'EPSG:32643'`).
- `resolutionGsd`: Ground Sample Distance in meters per pixel (e.g. `0.08`).
- `ingestedAt`: ISO timestamp.
- `checksum`: SHA-256 hash for data integrity.

---

## 4. Audit Trail & Human Edits

When a surveyor modifies a feature boundary in the WebGIS editor:
1. `properties.edited` becomes `true`.
2. `properties.status` transitions from `'detected'` or `'review'` to `'corrected'`.
3. An entry is appended to `editHistory` with timestamp and action (`"vertex_moved"`, `"polygon_split"`, `"boundary_aligned"`).
4. Previous geometry can be archived in history for rollback if needed.
5. Previous topology flags associated with the unedited geometry are queued for revalidation.
